02 / Turbo tags

Macro directives

Place a one-line comment immediately above a top-level named function. The macro scanner reads only standalone comments that share no line with code.

Luau
--@quantum:turbo
local function buildInventory()
  local frame = Instance.new("Frame")
  -- ...
  return frame
end

--@quantum:maximum
function Effects.explode(position)
  local attachment = Instance.new("Attachment")
  -- ...
end
Turbo

Native extraction

Eligible function bodies are lifted into native Luau where the engine can prove it is safe. No VM bytecode for that function.

Maximum

Native plus maximum grade

The function is processed at the maximum hardening grade. Use it for expensive visual construction with no sensitive control flow.

Rules the scanner enforces

  • The function must be a top-level statement with a stable name.
  • Function assignments such as local f = function() end are taggable when named and top-level.
  • Duplicate names are rejected: tag the declaration after the conflict is resolved.
  • Nested functions, anonymous callbacks, and nested IIFEs have no stable tag site.
  • Top-level IIFEs have no stable tag site until they are refactored into named functions.
  • A function with conflicting Turbo and Maximum directives is rejected by the scanner.
  • If native extraction would capture an upvalue, the engine safely vetoes extraction for that function.
No tag is not an error.

It only means the function is not a candidate for native extraction. The rest of the script still gets the selected VM or AST profile.

03 / Common blocker

How to Turbo an IIFE Script

An immediately invoked function expression has no stable top-level name, so there is nowhere legal to put a macro. The analyzer can now lift safe top-level IIFEs into named local functions, add the macro tag, and preserve the call and its arguments. Nested IIFEs still require a manual refactor.

Automatic refactor

  • Use Auto-Refactor All IIFEs in the banner to handle every safe top-level site at once.
  • Use Refactor IIFE on an individual finding to handle only that line.
  • Only direct top-level statements and direct values in top-level assignments, local declarations, compound assignments, and returns are eligible.
  • Arguments, trailing comments, indentation, and CRLF line endings are preserved. Existing Quantum directives are kept without duplication.
  • Generated names use the collision-free __quantum_iife_N form, and the transformed source is validated before it replaces the editor contents.
  • Nested IIFEs, type-asserted IIFEs, and sites with conflicting directives are never rewritten. The response reports them as remaining.

The comparison shows the same rewrite with a readable function name; the automatic action uses __quantum_iife_N so it cannot collide with existing locals.

Before — IIFE, cannot be tagged
(function()
  local panel = Instance.new("Frame")
  panel.Size = UDim2.fromOffset(320, 180)
  panel.Position = UDim2.new(0.5, -160, 0.5, -90)
  panel.Parent = playerGui
end)()
After — named top-level function, taggable
--@quantum:turbo
local function buildPanel()
  local panel = Instance.new("Frame")
  panel.Size = UDim2.fromOffset(320, 180)
  panel.Position = UDim2.new(0.5, -160, 0.5, -90)
  panel.Parent = playerGui
  return panel
end

local panel = buildPanel()

Manual refactor checklist for nested IIFEs

  1. Move the IIFE body into a new local function at the top level of the script.
  2. Pass values the body used to capture as parameters, or return them and keep the call site explicit.
  3. Return anything the surrounding code expected from the IIFE.
  4. Call the function once at the original invocation site.
  5. Add --@quantum:turbo on the line directly above the new function.
IIFE inside another function?

Lift it all the way to the script's top level. The automatic action intentionally leaves nested IIFEs unchanged, and moving them into another nested function does not make them taggable even if that function has a name.

Captured variables are still checked.

Naming the function makes it taggable, but native extraction is vetoed if the body captures an upvalue the extractor cannot prove safe. The engine falls back to the normal path instead of risking behavior.

Macro automation

Studio keeps macro preparation in the Analyzer and compilation in the Obfuscator. The Obfuscator never re-scans the source at protect time; it preserves the Quantum tags already in the editor. The local API still exposes backend auto-detection for external callers.

  • Analyzer Auto-Detect: the explicit Analyze button analyzes first, applies safe top-level fixes, then re-analyzes the tagged result. Auto Turbo level and Auto-detect live in the Quantum Exclusives panel.
  • IIFE guard: if the source contains IIFEs, the Analyzer shows the detected count and how many are safe to refactor. Use the banner action or a finding action for safe top-level sites; nested IIFEs stay manual.
  • API Auto-Detect: external callers may send autoDetectMacros and turboLevel. The backend scans a copy and reports autoMacros.injected plus skipped-function warnings.
  • Live typing: never auto-applies a fix while you are editing; it only refreshes diagnostics.
06 / Integration

Local API

The Studio UI uses the same public endpoints available to local tooling. The server binds to this machine and accepts JSON bodies.

GET/api/health

Returns { ok, service, version }.

POST/api/analyze

Body: { code, options: { tier } }. Returns diagnostics, macros, and summary counts. IIFE findings include a refactor: { line } action when safe.

POST/api/refactor-iifes

Body: { code, line?, options: { tier } }. Refactors all safe top-level IIFEs, or only the IIFE that starts on line. Returns code, refactored, remaining, and warnings.

POST/api/obfuscate

Body: { code, options }. Returns the protected output, elapsed time, resolved meta, and auto-macro details.

POST/api/validate
JavaScript — protect a script
const response = await fetch("/api/obfuscate", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    code: source,
    options: {
      profile: "maximum",
      target: "roblox",
      autoDetectMacros: true,
      turboLevel: "light",
      luraph: {
        intenseVM: true,
        useDebugLib: false,
        vmCompression: true
      }
    }
  })
});

const { output, durationMs, meta, autoMacros } = await response.json();
JavaScript — refactor safe IIFEs
const response = await fetch("/api/refactor-iifes", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    code: source,
    line: 12, // omit to refactor all safe top-level IIFEs
    options: { tier: "turbo" }
  })
});

const { code, refactored, remaining, warnings } = await response.json();

Omitting profile keeps the legacy path for older callers. Supplying profile activates Studio profile resolution. An invalid target, VM type, grade, or profile returns HTTP 400 with a JSON error.

Deterministic builds

Set a seed in the obfuscator settings to make repeated builds reproducible. With a blank seed, Studio creates a fresh random seed for every run and shows it in the output metadata.

07 / Repairs

Troubleshooting

The analyzer says a function is already tagged, but I want to change the tier.

Remove or replace the existing macro above the function. The analyzer intentionally does not offer an automatic tier replacement while both directives could exist.

My IIFE is not being refactored automatically.

Only safe top-level IIFEs are eligible. Nested, type-asserted, or directive-conflicting IIFEs are reported as remaining and left unchanged. Move nested sites to the script's top level using the manual checklist above, then run the analyzer again.

I see an antiTamper feature but the script targets Generic.

Intense VM can force hardening features regardless of target. Confirm the output target in the resolved metadata before shipping. Maximum with Roblox also enables executor globals and the Roblox bootstrap.

The obfuscator reports a parse error.

Run the analyzer first. Syntax errors block macro injection and protection. The error banner includes line and column details when the parser provides them.

My script is too large to send from the analyzer.

Browser storage has a per-origin quota. The UI keeps the draft in the current tab and reports when the handoff cannot fit. Paste the script directly into the obfuscator instead.

I want the old single-page behavior.

The four Studio routes are the supported interface. The API remains compatible with legacy request shapes that omit a profile.

08 / Trust boundary

Local by construction

Studio is a local tool. Source code, settings, and protected output travel only between the browser and the Express server on this machine. There is no account, upload queue, remote cache, or telemetry endpoint.

  • The web bundle is generated locally with esbuild and served from /assets/studio.js.
  • Obfuscation runs inside a worker with a timeout and its own resource boundary.
  • The server accepts up to 20 MB of UTF-8 source per request.
  • Drafts and the analyzer handoff use browser storage; they do not leave the browser.
